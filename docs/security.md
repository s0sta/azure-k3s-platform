# Security controls

| Area | Control | Where |
|---|---|---|
| Identity | GitHub → Azure with OIDC (no client secret); VMs use managed identities | `scripts/bootstrap-state.sh`, `terraform/modules/k3s-node` |
| Secrets | k3s join token generated by Terraform, stored in Key Vault (RBAC, purge protection); nodes may read only that secret | `terraform/main.tf` |
| State | Remote state in Azure Storage: Entra ID auth only (no shared keys), TLS 1.2, versioning, soft delete, ZRS | `scripts/bootstrap-state.sh`, `versions.tf` |
| Network | NSG deny-all with explicit allows; admin ports only from `admin_cidrs`; agents private; NAT egress | `terraform/modules/network` |
| VMs | Trusted Launch (secure boot, vTPM), SSH keys only, no root login | `modules/k3s-node`, `templates/cloud-init.yaml.tftpl` |
| OS hardening | patched + unattended security updates, strict sshd (modern ciphers, publickey only), sysctl, auditd rules, fail2ban | `ansible/roles/hardening` |
| Kubernetes | secrets encryption at rest, protect-kernel-defaults, Pod Security Admission (baseline enforced, restricted warned), API audit log, anonymous auth and profiling off, control plane tainted, WireGuard pod network | `ansible/roles/k3s` |
| Observability | metrics + alerts (Prometheus), logs + K8s audit log (Fluent Bit → Loki), host syslog (Azure Monitor) | `ansible/roles/platform`, `terraform/main.tf` |
| Delivery | fmt, validate, tflint, Trivy IaC scan on every PR; apply only after approval; nightly drift detection | `.github/workflows/` |
| Cost | budget with forecast alert, small VM sizes, 1 GB/day log cap | `terraform/main.tf` |

Accepted risk (documented in `terraform/.trivyignore`): the Key Vault public endpoint stays open for the lab;
production would use a private endpoint and `default_action = "Deny"`.
